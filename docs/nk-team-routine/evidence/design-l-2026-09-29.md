## 팀장 초안 설계

### R1 업로드 한 화면 (`/exams/new`)
- `?consultation=<id>` 로 학생 미리 선택(상담 상세의 여정 패널·분석 화면에서 "입학테스트 올리기" 버튼으로 진입). 선택돼 있으면 검색 칸 대신 학생 칩.
- 시험명 기본값 자동(`{학년} 입학테스트`)·시험일 오늘·과목 수학 → 한 줄 요약으로 접고 "수정" 누를 때만 펼침. 메모는 접힘.
- 드롭존 2개 나란히(좁은 화면은 위아래): 시험지(사진 여러 장, 휴대폰 카메라 `capture`) / 매쓰플랫 결과지(**PDF 그대로** 또는 사진, 최대 2). 썸네일·개별 삭제·파일별 진행률, 버튼 하나 "올리기".
- 버킷 `exam-papers` 허용 형식에 `application/pdf` 추가(크기 한도 20MB로). `scripts/exam-pull.mjs` 는 PDF 를 그대로 받는다(Claude 가 PDF 를 직접 읽음).

### R2 점수 자동 입력
- `exam_analyses` 에 칸 추가: `score_raw numeric`, `score_max numeric`, `score_grade text`, `score_summary text`(예: "약점: 접선의 방정식 12% · 강점: 도함수 100%"). `scripts/exam-push.mjs` 가 분석지 JSON 에서 채움. 박서진 1건은 적용 시 1회 채움(우리가 만든 새 데이터).
- 새 조회 `getLatestExamForConsultation(consultationId)` (status done/sent 중 최신). 등록 폼 `defaultValues` (`registration-form-client.tsx:301-302`) — 비어 있을 때만 `test_score` = "35/100 · 5등급 (미적분1 입학테스트 09.28)", `test_note` = `score_summary`. 화면에 "입학테스트에서 불러옴" 표시.
- `generateRegistration`(`registration.ts:568-578`) 에서 해당 상담의 `exam_analyses.student_id` 도 채움.

### R3 반 배정 도우미
- 순수 함수 `rankClassesForStudent(student, exam, classes)` + 단위 테스트. 입력: 학년, 점수·등급, 단원별 정답률(분석지 JSON `units[]`), 반 목록(학년 일치: 기존 `class-recommendation.ts:42` 규칙), 반별 `class_progress`(수준 상/중/하·속도·교재 진도 %·현재 대/소단원), `class_curriculum_progress`(단원·완료 여부), 학생 수, 요일·시간, 담당.
- 반마다 보여줄 것: 수준 적합(점수대 ↔ `ability_level`), **이미 지나간 단원 중 학생 약점**(따라잡기 필요), 지금 배우는 단원, 교재 진도 실제 vs 예상(기존 `computeExpectedPercent`). 단원 이름 매칭은 공백·기호 제거 후 포함 비교, 매칭 안 되면 "확인 필요"로 표시(추측 금지).
- 등록 폼 반 선택 옆 패널 + "이 반으로" 버튼 → 기존 `handleClassChange`. 입학테스트 상세에는 읽기 전용으로.
- 기존 `recommendClasses`(V1 요인 점수 기반)는 건드리지 않고 새 패널로 대체 표시.

### R4 상담 녹음·전사·분석
- 위치: 상담 상세(`consultation-detail-client.tsx`). 녹음 가능: principal·admin (신입 상담은 아직 반이 없어 선생님 열람 대상이 아님).
- **동의 단계 필수**: "보호자에게 녹음·전사·분석(구글 처리 포함) 목적과 원본 30일 뒤 삭제를 알리고 동의를 받았습니다" 체크 + 읽어 줄 안내문. `consent_at·consent_by·consent_version` 저장.
- 브라우저: `MediaRecorder` (`isTypeSupported` 로 webm/opus → mp4/aac), 32kbps, `timeslice` 10초. **20분마다 레코더를 새로 시작해 조각을 독립 파일로 만든다**(조각 ≈ 5MB). 조각 안의 10초 파트는 IndexedDB 에 쌓아 두었다가 조각 끝나면 업로드(새로고침·끊김 시 "복구 업로드"). Wake Lock + `visibilitychange` 재요청, "녹음 중 화면을 끄지 마세요" 안내, 경과 시간·저장된 조각 수 표시.
- 업로드: 서버가 권한 확인 후 `createSignedUploadUrl` 로 `consult-audio/{recordingId}/seg-{n}.{ext}` 발급 → 브라우저가 직접 업로드(Vercel 4.5MB 한도 회피). 버킷 private, 파일당 15MB, audio/* 일부만. **authenticated 용 storage 정책 없음**(서비스 롤 + 서명 URL 로만).
- 전사: route handler `POST /api/recordings/[id]/segments/[seq]/transcribe` (`runtime=nodejs`, `maxDuration=300`). 서비스 롤로 조각 다운로드 → Gemini `gemini-3.5-transcribe` (ko, 화자 구분) → 조각 전사 JSON `[{speaker,startSec,endSec,text}]` 저장. 조각 업로드 직후 브라우저가 호출(녹음 중에도 앞 조각부터 전사). 실패 시 "다시 전사".
- 분석: `POST /api/recordings/[id]/analyze` → 모든 조각 전사를 이어 붙여 `gemini-3.8-flash` 에 → zod 검증 JSON: 화자 매칭(원장/학부모/학생), 핵심 요약 3~5줄, 학생 현재 상태(성적·습관·태도), 학부모 요구·걱정, 약속한 후속 조치, 반 배정에 참고할 점, 주의 신호, 근거 인용(원문 발췌 몇 개). 숫자 지어내기 금지(전사에 없는 사실 금지).
- 모델 이름은 `env.ts` 에 기본값 있는 선택 변수: `GEMINI_TRANSCRIBE_MODEL=gemini-3.5-transcribe`, `GEMINI_CONSULT_MODEL=gemini-3.8-flash`. 기존 `GEMINI_MODEL`(설문, 3.6) 은 그대로.
- 표: `consultation_recordings`(id, consultation_id → consultations ON DELETE CASCADE, status recording/transcribing/transcribed/analyzing/analyzed/failed, mime, segment_count, duration_sec, consent_*, transcript jsonb, analysis jsonb, error, created_by, created_at, transcribed_at, analyzed_at, audio_delete_after, audio_deleted_at) · `consultation_recording_segments`(recording_id, seq, path, duration_sec, bytes, status, transcript jsonb, error, unique(recording_id, seq)). RLS 켬 + **정책 없음** + `REVOKE ALL FROM anon, authenticated` → 서버(서비스 롤)만 읽고 쓴다.
- 권한 판정(서버 공통 함수): 로그인 사용자 → `getCurrentTeacher()`(teachers.phone ↔ auth 이메일) → role principal/admin 이면 허용 / teacher 면 `consultations.student_id → students.class_name → classes(name) where teacher_id = 나` 일 때만 / 그 외 거부. 재생은 권한 확인 후 서명 URL(10분).

- **D4 전사** — 멱등 서버 함수: 조건부 UPDATE 로 선점(uploaded|failed, 또는 transcribing 인데 locked_at 10분 초과) → 조각 inline(base64) → `gemini-3.5-transcribe`(ko, 화자 구분) 전용 fetch 타임아웃 240초(`gemini.ts` 60초 재사용 금지) → 저장 / 실패 시 failed+error. **Files API 쓰지 않음**(구글에 48시간 사본). 호출 시점: 업로드 직후 브라우저 · 녹음 패널 열 때 남은 조각 1개씩 · 매일 cron 이 남은 것 처리(시간 예산 안). route `runtime=nodejs`, `maxDuration=300`.
- **D5 분석** — 마감(segment_count 확정) + 모든 조각 전사 완료일 때만 선점 → `gemini-3.8-flash` → zod 검증 JSON. 화자 매칭은 분석 단계에서(조각마다 라벨이 바뀔 수 있음). 실패 시 failed + "다시 분석".
- **D6 보관** — `audio_delete_after = created_at + 30일` INSERT 때 확정(늘리지 않음). 삭제: Vercel Cron 하루 1회 `/api/cron/recordings`(`Authorization: Bearer CRON_SECRET`, **CRON_SECRET 없으면 503 로 아무것도 안 함**) + 녹음 패널이 뜬 뒤 백그라운드로 만료분 최대 20건 정리. `storage.remove` 결과 수 == 요청 수일 때만 `audio_deleted_at` 기록, 아니면 error 기록·cron 500. 전사문·분석은 상담이 있는 동안 보관(동의 문구에 명시).
- **D7 상담 삭제** — FK `ON DELETE RESTRICT`. 상담 삭제 액션은 먼저 녹음 오디오 삭제(결과 확인) → 녹음 행 삭제 → 상담 삭제, 실패하면 상담 삭제 중단·안내.
- **D8 등록 자동 입력** — 상담 `test_score` 가 있으면 그게 우선, 시험값은 **빈칸일 때만**. `analyses/[id]/page.tsx` 서버에서 조회해 props 로(클라이언트 비동기 금지). "입학테스트에서 불러옴" 표시는 사용자가 고치면 숨김. `exam_analyses.student_id` 는 `.eq(consultation_id).is(student_id, null)` 가드, 실패는 로그만(등록을 막지 않음). 설문 목록의 빠른 등록(`survey-list-client.tsx`)은 이번 범위 밖.
- **D9 공유 계약**(T2 가 `src/lib/actions/exam-lookup.ts` 에 만든다) — `getLatestExamForConsultation(consultationId)` → 최신 1건(상태 무관) `{ id, status, examTitle, examDate, subject, reportToken, tokenUsable, score: {raw,max,grade}|null, scoreSummary, units: {name, me, national|null}[]|null }`. units 는 분석지 JSON 을 zod 로 검증해 읽음. 칸이 없거나(마이그레이션 전) 오류면 null + console.error.
- **D10 알림톡 토큰** — 발송 직전: revoked 면 거부, `expires_at = greatest(expires_at, now()+14일)`. 발송 성공 뒤에만 `status='sent'`·`sent_at`. 미승인(draft)이면 "카카오 심사 대기" 표시, 상태 변경 없음.
- **D11 반 배정** — 순위 신호 3개만(학년 일치 아니면 제외 · 점수대↔`ability_level` · 이미 지나간 단원 ∩ 학생 약점). 요일·학생 수·담당·진도 %는 **표시만**. 등록 폼에만 둔다(시험 상세에는 안 둠).
- **D12 소유권** — 분석 화면의 "입학테스트 올리기" 버튼은 T2(R5 버튼 옆). 상담 여정 패널의 올리기 링크는 T1(링크만, page.tsx 새 prop 없음). 상담 상세 page·client 는 T3.
- **D13 마이그레이션** — 100000(T2)·110000(T1)·120000(T3) 서로 독립. 전부 추가만, 멱등(`IF NOT EXISTS`·`ON CONFLICT DO NOTHING`·버킷 UPDATE 는 `NOT (… = ANY …)` 가드), 파일 끝에 "적용 후 확인" 주석과 되돌리기 SQL 주석. 적용은 팀장.
- **D14 새 환경변수**(env.ts, 전부 선택·기본값): `GEMINI_TRANSCRIBE_MODEL=gemini-3.5-transcribe`, `GEMINI_CONSULT_MODEL=gemini-3.8-flash`, `CRON_SECRET`(기본 빈 값 → cron 503). `vercel.json` crons `0 18 * * *`(03:00 KST).
